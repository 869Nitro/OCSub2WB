# OCSub2WB 使用手册

本手册对应 **v2.2.1**。首次安装可按仓库首页的[快速开始](../README.md#快速开始)操作，完整面板见[实际运行截图](../README.md#运行界面)。

## 下载、升级与恢复

从发布页下载 Windows x64 便携 ZIP，完整解压到有写入权限的目录，再运行 `OCSub2WB.exe`。两个 Python 脚本应与 EXE 放在一起。包内的脚本使用 Python 标准库，面板会优先查找 WorkBuddy 自带的 `pythonw.exe`，再查找系统 `PATH` 上的版本。[下载 v2.2.1](https://github.com/869Nitro/OCSub2WB/releases/tag/v2.2.1)

升级时，先在旧面板点 **退出** 并确认停止转发桥。把新包解压到新目录，再把旧便携目录中的 `.env` 复制过去以沿用 Key、上游代理和模型名称前缀。随后从新目录启动面板和转发桥，点一次 **一键配置**。

系统还原或迁移到新的 Windows 环境后，重新安装并登录 WorkBuddy。手头没有原来的 `.env` 时，在面板重新保存 Key 和代理配置。可从保存 Key 的对话框启动转发桥，等模型列表加载后再执行 **一键配置**。如要保留旧的模型配置备份，也可以保留旧目录的 `cache/backup/`。

发布页上的 `.sha256` 文件记录 ZIP 的校验值。可以用 PowerShell 对下载的 ZIP 计算 SHA-256，并与校验文件的第一列比较。

```powershell
Get-FileHash -Algorithm SHA256 .\OCSub2WB-v2.2.1-win64.zip
```

## 启停和窗口

- **启动转发桥**会开启本地服务。面板固定使用端口 `8787`，WorkBuddy 的接口基址为 `http://127.0.0.1:8787/v1`。
- 窗口的 **×** 会把面板收进系统托盘，转发继续运行。点托盘图标可以重新打开面板。
- 面板的 **退出** 和托盘菜单的 **退出并停止转发桥** 都会先询问再关闭服务。进行中的模型请求会中断。
- 面板支持拖边缩放、最大化和还原，默认尺寸是缩放下限。Windows 的显示工作区变化后，普通窗口会重新检查位置和尺寸。

## 额度和模型

转发桥停止时，输入新的 API Key 并点 **保存**。**仅保存 API Key** 只写入便携目录中的 `.env`，不联网校验，也不刷新模型列表。**保存并启动转发桥，刷新模型列表** 会依次保存、启动、联机校验并读取面板模型目录。已导入的托管模型会同步更新密钥，新模型可用 **一键配置** 导入。

**刷新用量**更新面板左上角的 5 小时、本周和本月额度及重置时间。用量来自 OpenCode Go 订阅。模型可用性、额度限制和数据规则以自己的 OpenCode 工作区为准。[OpenCode Go 额度说明](https://opencode.ai/docs/console/go/#usage-limits)

| 面板按钮 | 行为 |
| --- | --- |
| **一键配置** | 按最新目录重建 OCSub2WB 托管的聊天模型，包括目录中标记为免费的条目。目录里的免费标记和当前账号的可用性需要分别核对。 |
| **探测免费模型** | 向目录中的免费模型发起实际探测，查看当前工作区的可用性及区域、训练选项等限制。 |
| **导入列表至WB** | 重建托管列表，包含付费聊天模型和本次探测通过的免费模型。 |
| **测试已选模型** | 检查选中模型的普通对话和流式对话。最多发出两条模型测试请求。 |
| **刷新模型状态** | 更新面板的模型目录和导入状态。 |
| **清空WB列表** | 确认后备份并移除 OCSub2WB 托管的条目。 |

默认导入名称带 `[OC]` 或 `[OC-FREE]` 前缀。同步模型会保留独立配置的自定义条目。如果自定义模型已使用同一个模型 ID，现有条目优先。覆盖现有模型配置前会先备份，备份失败则保留原配置。

## 最近请求指标

右上角显示最近 **3 条成功完成**的模型转发请求，并发时按完成时间排序。记录按桥接请求计数，可以来自多个 WorkBuddy 会话，也可以来自同一轮对话或经过转发桥的后台调用。模型自测排除在外，重启转发桥后重新开始统计。

| 字段 | 计算方式 |
| --- | --- |
| **模型 ID** | 请求里使用的模型标识。窗口较窄时，过长的 ID 会以省略号结尾。 |
| **TTFT (s)** | 从转发桥开始上游请求，到收到首段非思考输出的秒数。正文、拒答文本和工具调用输出都可作为起点。角色占位、思考片段和用量事件不作为起点。 |
| **Tok/s** | 在流式输出用量可用且首末段有不同接收时间时，按 `(非思考输出 token 数 − 1) ÷ Δt` 估算本机接收速率。集中到达的分块会使读数偏高。模型输入、首段前的等待和末尾用量事件不参与此项计算。 |
| **Δt** | 首段到末段输出的接收间隔。短间隔用毫秒显示。 |

若上游给出了思考用量明细，转发桥据此扣除思考 token。已观察到思考但上游未给出可分开的用量时，速率显示 `—`。缺少用量或可计数输出不足两个 token 时，速率也显示 `—`。首末输出在同一次读取中到达时，速率与 Δt 都显示 `—`。只要有可识别的流式输出，TTFT 仍可显示。非流式请求的三项流式指标都显示 `—`。[OpenCode 用量字段](https://opencode.ai/docs/console/api/inference/#cost)

## 上游代理

上游代理设置控制转发桥**访问 OpenCode Go**时的网络路径。填写代理程序实际监听的 **HTTP** 地址，例如 `http://127.0.0.1:7897`，选择模式后点 **应用**。

| 模式 | 模型请求的路径 |
| --- | --- |
| **直连** | 转发桥直接访问 OpenCode Go。 |
| **自动** | 目录标记为锁区的模型走上游代理，其余模型直连。 |
| **手动** | 所有模型请求经配置的上游代理转发。 |

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 面板提示找不到 Python 或脚本 | 先打开 WorkBuddy，再确认 `OCSub2WB.exe` 和两个 `.py` 文件在同一目录。也可确认 `PATH` 上的 Python 3.10 或更高版本包含 `pythonw.exe`。 |
| 提示端口 8787 已被占用 | 确认是否仍有旧版转发桥在运行，先从旧面板正常退出，再从新版启动。 |
| WorkBuddy 无法连接或看不到新模型 | 确认转发桥已启动，保存 Key 后重跑 **一键配置**，回到 WorkBuddy 的模型设置重新选择模型。 |
| Key 保存失败，或收到 401／403 | 核对 Key、订阅工作区和地区设置。需要上游代理时，确认填写的是正确的 HTTP 端口且已应用。 |
| 免费模型提示需要训练 opt-in | 查看 OpenCode 工作区对该模型的训练选项，按自己的数据规则决定是否启用。 |
| 面板提示 `models.json` 已从备份只读加载 | 确认从备份恢复后再重试同步。被替换的原文件会以 `models.json.corrupt.<时间>` 保留。 |
| 最近请求的速度或 TTFT 显示 `—` | 核对是否为流式请求，以及上游是否分批传回输出和用量。可对照本页的[指标口径](#最近请求指标)。 |

可从 **打开日志目录** 查看请求路径、路由、状态码与耗时。排查时可先对照出问题请求前后的几行。

## 本地文件与数据

| 路径 | 用途 |
| --- | --- |
| 便携目录的 `.env` | 保存 OpenCode Go Key、上游代理和模型名称前缀。字段示例见 [`.env.example`](../.env.example)。 |
| `%USERPROFILE%\.workbuddy\models.json` | WorkBuddy 的自定义模型列表。 |
| 便携目录的 `cache/logs/` | 转发日志。 |
| 便携目录的 `cache/backup/` | 写入模型配置前的备份。 |
| 便携目录的 `cache/api.token`、`cache/proxy.pid` | 本机面板控制令牌以及转发桥进程信息。 |

API Key 以**明文**保存在 `.env` 和 WorkBuddy 的托管模型配置中。模型配置备份也可能包含 Key。公开分享日志、配置或截图前，请移除其中的 Key、控制令牌、会话标识和其他敏感信息。

转发桥监听本机回环地址。模型请求和认证信息由转发桥发往 OpenCode Go，并在启用上游代理时走选定的路径。上游的数据处理规则见[OpenCode Go 隐私说明](https://opencode.ai/docs/console/go/#privacy)。

## 命令行与构建

Windows 面板使用 `8787`。单独启动转发脚本时可以用 `--port` 自选监听端口，并将客户端基址指向对应端口。命令行参数见脚本自带的帮助。

```powershell
python -B .\opencode-go-proxy.py --help
```

构建 Windows 面板需 MinGW-w64 和 Python 3.10 或更高版本。将 `g++`、`windres` 放到 `PATH`，或将 `MINGW` 指向工具链的 `bin` 目录，再从仓库根目录运行：

```powershell
python -B -m unittest discover -s tests
.\panel\build.bat --ci
```

构建后的 EXE 位于仓库根目录。用两个 Python 脚本与 EXE 从同一目录启动。GitHub Actions 会运行离线测试、校验 Windows x64 包并测试解压后的面板。[构建工作流](../.github/workflows/build-release.yml)
